# Web inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the textual-serve browser view behind `meute web` with a real HTML page over the same inbox data and actions, plus a Run tab that plans, stages (user-selected repos only), executes and tracks fleet work.

**Architecture:** A stdlib `http.server` script (`tui/webserver.py`) serves a static page and JSON endpoints that call `lib/inbox.py` (`dump`, `finding_body`, `act`) and a run controller (`tui/runctl.py`) that shells out to `bin/meute plan` and `bin/run.sh`. State-changing requests are guarded by a per-process token plus `Host`/`Origin` checks. The Textual app stays for `meute tui`.

**Tech Stack:** Python 3.11+ stdlib only; vanilla HTML/JS/CSS; bash (`lib/plan.sh`, `bin/meute`); `unittest` plus the bash harness `tests/test_meute.sh`.

**Spec:** `docs/superpowers/specs/2026-11-15-web-inbox-design.md` (v1 + addendum v2)

## Global Constraints

- Python standard library only; no node, no build step, no new dependency.
- Binds `127.0.0.1` by default; non-loopback keeps the `--host` + `--insecure-public` gate in `cmd_web` (`bin/meute:672`).
- Every POST requires header `X-Meute-Token` == per-process token, `Host` == bound `host:port`, and (if present) `Origin` == `http://<host>:<port>`.
- Report/evidence text is untrusted: render with `textContent`, never `innerHTML`.
- `bin/run.sh` must not reference `tui/` (invariant at `tests/test_meute.sh:3174`); the runner's quota floor is never bypassed or reimplemented.
- Every triage action goes through `inbox.act(verb, rid, n, *rest)`; the page adds no decision logic.
- Enqueue stages only paths the user ticked AND that appear in a fresh server-side plan; empty selection is rejected.
- Start refuses (409) while paused (`state/hold`) or a loop is already running; one loop at a time; 3 consecutive `status=error` runs stop it.
- Files under 400 lines; handlers do not mutate shared state.

## Review Focus

- POST with valid token but foreign `Host` (DNS rebinding): 403, nothing executed.
- Dismiss with empty reason / resolve with empty message: 400 (the CLI requires both).
- `n` not a positive int; `id` with path characters (`../`): 400.
- Report text containing `<script>`: shown literally.
- `act` returns `{ok:false}`: surfaced, row kept.
- Enqueue with a path not in the fresh plan (e.g. `/scan-root/private-docs` after it was enrolled or removed), or with zero paths: rejected, `state/plan-queue.json` untouched.
- Double-click on Start, or Start while `state/hold` exists: second call 409, no second loop.
- Runner exits 0 with `status=skipped` (nothing eligible, quota gate, pause): loop ends cleanly, not as an error, with the logged `reason=` shown.
- Server stopped mid-run: loop stops after the in-flight item; the item is not killed.

### Task 4: Run controller and endpoints

**Files:** Create `tui/runctl.py`; Modify `tui/webserver.py`; Test `tests/test_runctl.py`, `tests/test_webserver.py`

**Interfaces:**
- Consumes: `bin/meute plan --json`, `bin/meute plan --enqueue --only …`, `bin/run.sh daily`; `state/hold` (pause marker), `state/plan-queue.json` (`{entries: [{name, path, task, spec}]}`), `state/log` (tab-separated, first field ISO timestamp, then `key=value` fields incl. `status=ok|skipped|error`, `repo=`, `task=`, `reason=` on skipped).
- Produces: class `RunController(root: str, runner=subprocess_runner)` with `plan() -> dict` (the `--json` object), `enqueue(paths: list[str]) -> dict` (`{ok, message, staged}`; raises `ValueError` for empty or path not in a fresh `plan()`), `start() -> dict` (raises `RunConflict` if paused or already running), `stop() -> None`, `status() -> dict` `{state: idle|running|stopping, current: {repo, task}|None, total: int, done: int, remaining: int, stopped_reason: str|None, recent: [{time, status, repo, task}]}`. Endpoints: `GET /api/plan`, `POST /api/enqueue {paths}`, `POST /api/run/start`, `POST /api/run/stop`, `GET /api/run/status`; `RunConflict` → 409, `ValueError` → 400.
